## 2. Эпик: интеграции с CRM (Bitrix24, amoCRM)

Источники: ADR-004 (первая интеграция после MVP — amoCRM или Telegram Business, по итогам H-06), PRD §18, §21, §28, [product-direction-options.md §4, §8](../discovery/product-direction-options.md#4-вариант-1--углубить-инструмент-реакции). Цель — убрать двойной ввод для подсегмента (а) «с CRM».

### 2a. Сейчас, без кода: подключение через Make / n8n / Albato — P1, S

Клиент настраивает сценарий в сервисе-посреднике: событие «новый лид/сделка» в CRM → HTTP-запрос `POST /intake/leads` с заголовком `X-Api-Key` (ключ из «Настройки → API-ключи»). Нам нужна только инструкция (RU/UZ) с готовыми шаблонами сценариев.

| Поле CRM | Поле Vippi (intake API) | Примечание |
|---|---|---|
| Имя контакта | `fullName` | Нужно имя **или** телефон |
| Телефон | `phone` | Только +998 (ADR-024) |
| Канал / источник | `source` | Свести к `INSTAGRAM`, `TELEGRAM`, `WEBSITE`, `OLX`, `PHONE`, `WALK_IN`, `REFERRAL`, `OTHER` |
| Кампания, UTM | `sourceDetail` | Свободный текст до 100 символов |
| ID лида/сделки в CRM | `externalId` | Идемпотентность: повтор не создаёт дубль (CONFIRMED, `Lead_org_externalId_key`) |
| Текст заявки | `message` | До 4000 символов |
| Свои поля | `attributes` | Ключи — из «Поля лида»; `required` для intake не проверяется (ADR-024) |

**Ограничение (TBD, проверить по официальной документации [amoCRM](https://www.amocrm.ru/developers/) и [Bitrix24](https://apidocs.bitrix24.ru/)):** исходящие вебхуки CRM, по нашим данным (HYPOTHESIS), не позволяют задать свой заголовок `X-Api-Key` и присылают только ID сущности в формате `x-www-form-urlencoded`, а не наш JSON. Поэтому прямой вебхук «CRM → Vippi» не сработает: нужен посредник (Make/n8n/Albato) или отдельный входящий endpoint со своим секретом в URL (этап 2c).

**Критерии приёмки:** инструкция в `docs/` и в UI страницы API-ключей; проверенный сценарий хотя бы для одной CRM на тестовом аккаунте; лид приходит с `externalId` и SLA; повтор того же события не создаёт дубль.

### 2b. Исходящие: Vippi → CRM — P1, M (рекомендуется первым)

Порядок — по [product-direction-options.md §8](../discovery/product-direction-options.md#8-бэклог-на-24-недели-рекомендуемый-путь), задача 4.
1. **Подписанные вебхуки** (`WebhookEndpoint` + outbox `WebhookDelivery`): события `lead.created`, `lead.first_response`, `lead.sla_breached`, `lead.status_changed`; HMAC-подпись, at-least-once с повторами, защита от SSRF. Подходит для Make/n8n и любой CRM. ~1,5 нед.
2. **Нативная отправка в amoCRM/Bitrix24:** создать лид/сделку, обновить статус, добавить комментарий (примечание) — через REST CRM поверх того же outbox. Требует хранения токенов (см. 2c).

### 2c. Нативный входящий коннектор — P2, L

- **Страница «Настройки → Интеграции»** (владелец, новое право `integrations.manage`): подключить/отключить, статус, последняя синхронизация.
- **Авторизация:** amoCRM — OAuth 2.0 (refresh-токены); Bitrix24 — локальное приложение или входящий вебхук (TBD, выбрать на спайке).
- **Хранение секретов:** модель `Integration` (`kind`, `status`, `config`, `externalAccountId`); токены шифруются так же, как API-ключи — `sealSecret`/`openSecret` (AES-256-GCM, `organizationId` как AAD) в `apps/api/src/common/crypto.ts`. Ключ шифрования — отдельный env, не в логах и не в ответах API.
- **Получение лидов:** подписка на события CRM → по ID забираем сущность через REST CRM → создаём лид через тот же код, что intake API.
- **Сопоставление полей:** экран маппинга (поля CRM → `fullName`, `phone`, `source`, `sourceDetail`, `attributes`), этапы воронки CRM → наши 5 статусов.
- **Двусторонняя синхронизация статусов:** отдельный путь для интеграций — переходы не через `canTransition` пользователя, каждое изменение пишется в аудит (product-direction-options.md §4, «Статусная машина»). Защита от петель (изменение, пришедшее из CRM, не отправляется обратно).
- **Дедупликация** по `externalId`.
- **Журнал ошибок и повторов:** последние N событий с кодом ошибки (без ПДн), повтор вручную, автоотключение после серии неудач.

**Критерии приёмки:** новый лид в CRM появляется в Vippi ≤1 мин с SLA; смена статуса в Vippi видна в CRM и наоборот без петель; повтор события не создаёт дубль; токены в БД только зашифрованы; отозванный доступ в CRM переводит интеграцию в статус «ошибка» с понятным сообщением; тесты изоляции тенантов (событие одной организации не попадает в другую) и матрица доступа зелёные.

**Риски:** изменения API и правил маркетплейсов CRM (нужна публикация/ревью приложения — TBD); лимиты частоты запросов (порядка единиц запросов в секунду на аккаунт — HYPOTHESIS, проверить) → очередь и backoff; изоляция тенантов — входящий вебхук определяет организацию только по секрету/аккаунту, никогда по телу запроса (ADR-014); утечка токенов — шифрование, ротация, аудит; потеря деталей при сведении чужой воронки к 5 статусам; ADR-011 — решить, хватает ли outbox под advisory lock или нужен pg-boss.

**Объём (HYPOTHESIS, product-direction-options.md §4):** amoCRM — 4–6 нед.; Bitrix24 — 3–4 нед.; перед этим спайк по документации обеих CRM 2–3 дня.
