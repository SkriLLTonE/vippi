## 1. Принципы исполнения

1. **Вертикальные срезы:** каждый день заканчивается работающим end-to-end функционалом (API + UI + тесты), а не «слоем».
2. **Режем объём, не качество** (ADR-003): при отставании — снимаем только 6 опциональных функций по утверждённой cut-line (раздел 4), но не тесты изоляции, не валидацию и не обработку ошибок. Приоритет заказчика (CONFIRMED): сначала безопасность данных и работающий основной бизнес-процесс, затем аналитика и удобство.
3. **Fallback-first для AI:** сначала rule-based режим и e2e без ключа, затем адаптеры провайдеров.
4. **DoD** — SPEC, раздел 28. Статус всех задач на старте — `TODO`. Фактические статусы на 2026-10-21 и пояснения к `PARTIAL` — раздел 7.
5. Ежедневная контрольная точка: в конце дня `docker compose up --build` с нуля + прогон тестов; при отставании >0,5 дня — применить следующую позицию cut-line; если позиции исчерпаны — правило эскалации (раздел 4.1).

## 4. Cut-line (что снимается первым при отставании)

**Статус: CONFIRMED заказчиком 2026-10-21** (interview-notes Q15, ADR-003, PRD §17.1).

Снимать строго по порядку, по одной позиции, при отставании >0,5 дня от плана; о каждом снятии сообщать заказчику. Снятые функции переводятся в roadmap PRD §28. Telegram-бот и AI-провайдеры OpenAI/Anthropic в cut-line не входят — они вне MVP изначально.

### 4.0. Правила применения cut-line (CONFIRMED 2026-10-21, Q18, ADR-020)
1. Безопасность никогда не снижается.
2. Режем UI, а не целостность данных (например, скрываем экран аудита, но события аудита продолжают записываться).
3. Не удаляем функции преждевременно: снятие — через feature flag (`DISABLED_FEATURES`, флаги `AUDIT_LOG_UI`, `WEEKLY_SUMMARY`, `BUSINESS_HOURS`, `DAILY_CHART`, `CSV_IMPORT_PREVIEW`, `DEAL_SCORE`) без поломки архитектуры, чтобы функцию можно было вернуть.
4. Каждое снятие записывается в decisions.md («Журнал снятий cut-line»): причина, последствия, условия возврата.
5. Если после снятия всех 6 пунктов срок всё равно не выдерживается — эскалация (4.1); обязательные требования не сокращаются.

**Никогда не снимается (CONFIRMED заказчиком):** изоляция тенантов и её тесты; SLA и уведомления; AI-сводка лида и черновик ответа с fallback и честной маркировкой; два языка RU/UZ; E2E-тесты основных бизнес-сценариев.
**Также обязательно** (всё, что не входит в шесть пунктов выше): аутентификация и сессии; роли и проверка прав на сервере; лиды, статусы, первый контакт, история; «Без реакции»; KPI дашборда и таблицы по менеджерам/источникам; CSV-импорт с отчётом об ошибках; intake API с ключами; адаптер Gemini; демо-сид и баннер; запись аудита; единый формат ошибок и состояния экранов; нефункциональные проверки T-033 (нагрузочный замер, Lighthouse, мобильные раскладки) — ранее предлагавшиеся как кандидаты на снятие, в утверждённый список не вошли.

### 4.1. Правило эскалации (CONFIRMED)

1. Если после снятия **всех шести** опциональных функций срок всё равно не выдерживается, разработка не урезает ничего сверх списка самостоятельно.
2. Исполнитель готовит заказчику оценку: сколько дней не хватает, какие обязательные задачи под угрозой и два варианта — (а) перенос срока на N дней, (б) перенос конкретных обязательных функций в следующую итерацию с явным согласием заказчика.
3. Решение принимает только заказчик. **Обязательные требования (безопасность данных, изоляция тенантов, основной бизнес-процесс, RU/UZ, E2E) не сокращаются ни при каких условиях** — их качество не снижается ради срока.
4. Момент эскалации — не позже конца дня 5, если по ежедневной контрольной точке видно, что шести пунктов недостаточно.

**Качество, закрытое 2026-10-21** (найденные и исправленные дефекты):

1. AI rule-based: `\b` не работает с кириллицей («дом» не распознавался) и не определялся смешанный RU/UZ-латиница текст.
2. AI rule-based: регулярное выражение суммы было квадратичным на длинных цифровых строках (14 с на 50 000 цифр → линейное). Нашёл CI: тест «длинный текст ≤500 мс» падал на раннерах GitHub.
3. Формы входа/регистрации: на пустом поле показывалось «неверный формат» вместо «обязательное поле».
4. Web, a11y:
   - диалоги не возвращали фокус на кнопку-открыватель (все диалоги приложения);
   - горизонтальный скролл дашборда на 390 px;
   - цели касания < 24 px (WCAG 2.5.8);
   - `font-size: 14px` на `html` игнорировал настройку размера шрифта пользователя.
5. Web, производительность: chunk recharts (370 kB) предзагружался на всех страницах из-за общей зависимости `clsx`. Начальная загрузка 1217 → 856 kB (gzip 368 → 264 kB).
